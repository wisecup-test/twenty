<rule_activation id="833f9b7e-2a5c-4efd-9f5a-9eb7214b6aa2" title="Adopt Storybook Stories for UI Component Documentation and Visual Testing: Reusable Input Components" applies_to="packages/twenty-front/src/**/*.tsx">
These rules are ALWAYS ACTIVE for all reusable UI input components in the twenty-front package.
</rule_activation>

### Rules

- **R-SB-001** MUST: All reusable UI input components MUST have corresponding Storybook story files with the `.stories.tsx` extension.

### Verify

```bash
# Count story files in the codebase
find packages/twenty-front/src -name '*.stories.tsx' | wc -l

# Verify story files export valid Storybook Meta objects
grep -r "export default.*Meta" packages/twenty-front/src/**/__stories__/*.stories.tsx

# Verify Storybook builds successfully
npm run storybook:build && test -d storybook-static
```

**Accept when:**
- All reusable UI input components have corresponding story files in `__stories__` directories
- Story files follow the naming convention `{ComponentName}.stories.tsx` and export valid Storybook Meta objects
- Storybook builds successfully without errors and generates static output
- Visual regression tests run in CI pipeline and catch component changes
- Story file updates are included in definition of done for component changes
- Automated checks detect components without stories

**Exceptions:**
- EXC-001: Component is deprecated and scheduled for removal within the current sprint
- EXC-002: Component is a temporary prototype or experimental feature not intended for production

<enforcement>
Claude Code MUST NOT skip or defer verification. All reusable UI input components in scope MUST have corresponding Storybook story files. CI pipeline MUST fail if new components are added without story files. Pull requests MUST be blocked until story files are added and reviewed.
</enforcement>
