<rule_activation id="616c930a-2462-4dfd-ae6e-ff8cd74d7ab5" title="Adopt Zapier Integration Pattern for External API Exposure: Integration Packages Use" applies_to="packages/twenty-*/src/**/*">
These rules are ALWAYS ACTIVE for all integration packages exposing external APIs through Zapier and similar third-party platforms.
</rule_activation>

### Rules

- **R-ZAP-001** SHOULD: Integration packages SHOULD use modern build tooling (e.g., Vite) to ensure compatibility with external platform requirements.
- **R-ZAP-002** MUST: All external data contracts MUST be defined in dedicated `.types.ts` files with comprehensive JSDoc documentation.
- **R-ZAP-003** MUST: Standard trigger patterns (list_record_ids for polling, trigger_record for webhooks, find_object_names for dynamic configuration) MUST be implemented in integration packages.
- **R-ZAP-004** MUST: Integration packages MUST follow the established `packages/twenty-{platform}` naming convention (e.g., twenty-zapier).
- **R-ZAP-005** MUST: External API endpoints MUST implement OAuth 2.0 authentication, rate limiting, audit logging, and scope-based permissions.
- **R-ZAP-006** MUST: Integration packages MUST NOT expose direct database access patterns or internal schema details.
- **R-ZAP-007** SHOULD: Integration documentation and visual components SHOULD be co-located in website sections for improved discoverability.
- **R-ZAP-008** MUST: Type definitions MUST be automatically generated from core API schemas to prevent drift between core API and integration packages.

### Verify

```bash
# Verify integration packages exist with platform-specific naming
find packages -type d -name 'twenty-*' | grep -E '(zapier|integration)' | wc -l

# Verify standard trigger patterns are implemented
grep -r 'list_record_ids\|find_object_names\|trigger_record' packages/twenty-zapier/src/triggers/ | wc -l

# Verify type definition files exist for external data contracts
find packages/twenty-zapier -name '*.types.ts' -o -name 'data.types.ts' | wc -l

# Verify modern build tooling is configured
grep -r 'vite.config' packages/twenty-zapier/ | wc -l
```

**Accept when:**
- At least one integration package exists under `packages/` with platform-specific naming (e.g., `twenty-zapier`)
- Standard trigger patterns (`list_record_ids`, `find_object_names`, `trigger_record`) are implemented in the integration package
- Type definition files exist for external data contracts with JSDoc documentation
- Modern build tooling (Vite or equivalent) is configured for integration packages
- OAuth 2.0 authentication is implemented for all external API endpoints
- No direct database access or internal schema exposure exists in integration code
- Integration documentation is co-located with integration package code

<enforcement>
Claude Code MUST verify all R-ZAP rules before approving changes to integration packages. CI pipeline MUST fail if integration packages are missing required trigger patterns, type definitions, or authentication mechanisms. Pull requests MUST be blocked if external API changes are not reflected in integration package types. Security scanning MUST flag any direct database access in integration code. Monthly architecture reviews MUST identify and remediate pattern violations.
</enforcement>
