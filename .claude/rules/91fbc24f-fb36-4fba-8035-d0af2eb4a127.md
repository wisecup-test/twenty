<rule_activation id="91fbc24f-fb36-4fba-8035-d0af2eb4a127" title="Implement Cache Layer for External API Relationship Data: Cache Layer Implementations" applies_to="**/*">
These rules are ALWAYS ACTIVE for all external API integrations that expose relational data models, frontend components that render or manipulate relationship data, API client libraries, and data persistence hooks for relational API data.
</rule_activation>

### Rules

- **R-CACHE-001** SHOULD: Cache layer implementations SHOULD provide hooks or interfaces for monitoring cache hit rates and performance metrics.

### Verify

```bash
# Detect cache-relationship patterns in TypeScript files
grep -r 'cache.*relationship\|relationship.*cache' --include='*.ts' --include='*.tsx' packages/

# Search for cache layer and relationship handling utilities
grep -r 'useMorphPersist\|cache_layer\|cacheRelation' --include='*.ts' --include='*.tsx' packages/

# Find cache implementation files with relationship logic
find . -type f -name '*cache*.ts' -o -name '*Cache*.ts' | xargs grep -l 'relationship\|relation'
```

**Accept when:**
- Cache layer implementation is detected in API integration modules with relationship handling logic
- Cache invalidation logic is present alongside relationship persistence operations
- Monitoring or metrics collection for cache performance is implemented or documented

<enforcement>
Claude Code MUST verify cache layer implementations for external API relationship data integrations. Verification is mandatory before accepting new external API integrations or relationship persistence patterns. Performance testing MUST validate cache hit rates meet defined thresholds (e.g., >70% for stable relationship data). Violations require written justification in architecture review or mandatory cache implementation work.
</enforcement>
