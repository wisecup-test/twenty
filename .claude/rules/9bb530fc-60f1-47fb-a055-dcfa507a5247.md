<rule_activation id="9bb530fc-60f1-47fb-a055-dcfa507a5247" title="Adopt Custom Canvas-Based Visual Effects Hooks for Design System Theming: Effect Hooks Colocated" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files implementing custom canvas-based visual effects hooks in the design system.
</rule_activation>

### Rules

- **R-CANVAS-001** MUST: Effect hooks MUST be colocated with their consuming components in a 'hooks' subdirectory within the component or section directory.
- **R-CANVAS-002** MUST: All canvas-based effect hooks MUST properly implement cleanup logic using useEffect return functions.
- **R-CANVAS-003** MUST: Effect hooks MUST follow the 'use-[effect-name]' naming pattern.
- **R-CANVAS-004** SHOULD: Create a shared utilities module for common canvas operations (context setup, animation frame management, cleanup patterns) to reduce duplication.
- **R-CANVAS-005** SHOULD: Document the standard hook structure including useEffect for lifecycle, useRef for canvas elements, and cleanup patterns in a design system guide.
- **R-CANVAS-006** SHOULD: Consider creating a base hook or helper functions for requestAnimationFrame management to ensure consistent animation patterns.
- **R-CANVAS-007** SHOULD: Add TypeScript types for hook return values and configuration parameters to improve developer experience.
- **R-CANVAS-008** SHOULD: Ensure all canvas effects are decorative only or provide equivalent ARIA labels and semantic HTML alternatives for accessibility.
- **R-CANVAS-009** SHOULD: Implement performance monitoring, provide fallback options, and use feature detection to disable effects on constrained devices.

### Verify

```bash
# Count custom effect hooks following naming pattern in hooks subdirectories
find . -path '*/hooks/use-*.ts' -type f | grep -E '(halftone|canvas|layout|effect)' | wc -l

# Verify canvas API usage in effect hooks
grep -r 'requestAnimationFrame\|canvas\.getContext' --include='use-*.ts' | wc -l

# Verify cleanup logic implementation in effect hooks
grep -r 'useEffect.*return.*=>.*cancel' --include='use-*.ts' | wc -l
```

**Accept when:**
- At least 3 custom effect hooks exist following the 'use-[effect-name]' naming pattern in the website sections
- All canvas-based effect hooks properly implement cleanup logic using useEffect return functions
- Effect hooks are colocated within 'hooks/' subdirectories of their consuming components or sections
- Canvas operations are properly isolated in utility functions or base hooks
- TypeScript types are defined for hook return values and configuration parameters
