<rule_activation id="e5015390-8c91-46cf-9728-39cb2b14bb9a" title="Implement Cache Layer for External API Relationship Data: Applications Implement Optimistic" applies_to="**/*">
These rules are ALWAYS ACTIVE for all external API integrations that expose relational data models and frontend components that render or manipulate relationship data.
</rule_activation>

### Rules

- **R-CACHE-001** MAY: Applications MAY implement optimistic caching strategies where relationship data is pre-fetched based on usage patterns

### Verify

```bash
# Detect cache layer implementation in API integration modules
grep -r 'cache.*relationship\|relationship.*cache' --include='*.ts' --include='*.tsx' packages/

# Search for cache-related patterns and relationship handling
grep -r 'useMorphPersist\|cache_layer\|cacheRelation' --include='*.ts' --include='*.tsx' packages/

# Find cache implementation files with relationship logic
find . -type f -name '*cache*.ts' -o -name '*Cache*.ts' | xargs grep -l 'relationship\|relation'
```

**Accept when:**
- Cache layer implementation is detected in API integration modules with relationship handling logic
- Cache invalidation logic is present alongside relationship persistence operations
- Monitoring or metrics collection for cache performance is implemented or documented
- Cache hit rates meet defined thresholds (e.g., >70% for stable relationship data)
- Cache key strategies incorporate entity IDs and relationship types to avoid collisions
- Cache TTL configurations and invalidation triggers are documented

<enforcement>
Claude Code MUST verify cache layer implementation for all external API integrations exposing relational data. Verification is mandatory before accepting new API integration code. Performance testing validating cache effectiveness is required for acceptance.
</enforcement>
