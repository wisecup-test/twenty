<rule_activation id="38729d61-60eb-4b0e-8791-5bab8faa6c83" title="Standardize Field Input Hooks Pattern for Record Field UI Components: Field Input Hooks" applies_to="packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/**">
These rules are ALWAYS ACTIVE for all field input components and hooks in the record-field UI meta-types/input module.
</rule_activation>

### Rules

- **R-FIH-001** MUST: Field input hooks MUST be located in the 'hooks' directory within the meta-types/input module structure at `packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks/`.
- **R-FIH-002** MUST: Follow the naming convention `useOpen[FieldType]FieldInput` for all field input hooks.
- **R-FIH-003** MUST: Place field input components in the parallel `components/` directory at `packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/components/`.
- **R-FIH-004** MUST: Name field input components using the pattern `[FieldType]FieldInput`.
- **R-FIH-005** MUST: Each field input component MUST use its corresponding dedicated hook.
- **R-FIH-006** SHOULD: Ensure hooks return consistent interface patterns (e.g., open handlers, state values, callbacks) to maintain API predictability across field types.
- **R-FIH-007** MAY: Simple field types (text, number, boolean) that require minimal state management and do not benefit from dedicated hooks are excepted from this pattern (EXC-001).

```bash
# Verify hook files exist and follow naming convention
find packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks -name 'useOpen*FieldInput.tsx' | wc -l

# Verify components use their corresponding hooks
grep -r 'useOpen.*FieldInput' packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/components/ | wc -l

# Verify directory structure is valid
test -d packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks && test -d packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/components && echo 'Structure valid'
```

**Accept when:**
- All field input hooks follow the `useOpen[FieldType]FieldInput` naming pattern and are located in the hooks directory
- Each field input component in the components directory uses its corresponding dedicated hook
- The directory structure maintains separation between `hooks/` and `components/` within the meta-types/input module
- No field input components exist outside the designated components directory
- No field input hooks exist outside the designated hooks directory
