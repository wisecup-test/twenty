<rule_activation id="19fa4b67-0e49-4a5e-87bc-8bcac58806eb" title="Adopt Zapier Integration Pattern for External API Exposure: Public Documentation Located" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching integration packages, external API code, and related documentation.
</rule_activation>

### Rules

- **R-ZAP-001** SHOULD: Public API documentation SHOULD be co-located with integration code in website sections for discoverability.
- **R-ZAP-002** MUST: All Zapier integration triggers and actions MUST follow standard trigger patterns (list_record_ids, find_object_names, trigger_record).
- **R-ZAP-003** MUST: External data contracts MUST be defined in dedicated .types.ts files with comprehensive JSDoc documentation.
- **R-ZAP-004** MUST: Integration packages MUST be created under packages/twenty-{platform} following the established twenty-zapier structure.
- **R-ZAP-005** MUST: All external API endpoints MUST implement OAuth 2.0 authentication, rate limiting, audit logging, and scope-based permissions.
- **R-ZAP-006** MUST: Integration packages MUST use modern bundlers (Vite or equivalent) for compatibility and bundle size optimization.
- **R-ZAP-007** MUST: Type definitions MUST be automatically generated from core API schemas to prevent drift between core API and integration packages.
- **R-ZAP-008** MUST: Integration code MUST NOT expose direct database access patterns or internal schema information.
- **R-ZAP-009** SHOULD: Integration packages SHOULD be versioned independently from core application.
- **R-ZAP-010** MUST: Comprehensive error handling and logging MUST be implemented to aid debugging of integration issues.

### Verify

```bash
# Verify integration package structure and naming
find packages -type d -name 'twenty-*' | grep -E '(zapier|integration)' | wc -l

# Verify standard trigger patterns are implemented
grep -r 'list_record_ids\|find_object_names\|trigger_record' packages/twenty-zapier/src/triggers/ | wc -l

# Verify type definition files exist
find packages/twenty-zapier -name '*.types.ts' -o -name 'data.types.ts' | wc -l

# Verify modern build tooling is configured
grep -r 'vite.config' packages/twenty-zapier/ | wc -l
```

**Accept when:**
- At least one integration package exists under packages/ with platform-specific naming (e.g., twenty-zapier)
- Standard trigger patterns (list_record_ids, find_object_names, trigger_record) are implemented in the integration package
- Type definition files exist for external data contracts with JSDoc documentation
- Modern build tooling (Vite or equivalent) is configured for integration packages
- OAuth 2.0 authentication is implemented for all external API endpoints
- No direct database access or internal schema exposure exists in integration code
- Integration documentation is co-located with integration code in website sections

<enforcement>
Claude Code MUST NOT skip or defer verification. CI pipeline MUST fail if integration packages are missing required trigger patterns or type definitions. Pull requests MUST be blocked if external API changes are not reflected in integration package types. Security scanning MUST flag any direct database access or internal schema exposure in integration code. Monthly architecture reviews MUST identify and remediate pattern violations.
</enforcement>
