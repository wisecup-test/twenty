<rule_activation id="87085bdf-2589-4791-b381-83320e9069dc" title="Adopt Zapier Integration Pattern for External API Exposure: Integration Packages Include" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching integration packages and external API exposure patterns.
</rule_activation>

### Rules

- **R-ZAP-001** MAY: Integration packages MAY include visual components for marketing and documentation purposes in website sections.
- **R-ZAP-002** MUST: All external data contracts MUST be defined in dedicated `.types.ts` files with comprehensive JSDoc documentation.
- **R-ZAP-003** MUST: Standard trigger patterns (list_record_ids for polling, trigger_record for webhooks, find_object_names for dynamic configuration) MUST be implemented in integration packages.
- **R-ZAP-004** MUST: Integration packages MUST use modern bundlers (Vite or equivalent) to ensure compatibility with platform requirements and optimize bundle size.
- **R-ZAP-005** MUST: All external API endpoints MUST implement OAuth 2.0 authentication, rate limiting, audit logging, and scope-based permissions.
- **R-ZAP-006** MUST: Integration packages MUST be created under `packages/twenty-{platform}` following the established `twenty-zapier` structure.
- **R-ZAP-007** MUST: Comprehensive error handling and logging MUST be implemented to aid debugging of integration issues.
- **R-ZAP-008** SHOULD: Integration documentation and visual components SHOULD be co-located in website sections for improved discoverability.
- **R-ZAP-009** MUST: Type definitions MUST be automatically generated from core API schemas to prevent drift between core API and integration packages.
- **R-ZAP-010** MUST: Contract testing and strict TypeScript compilation MUST be enforced to catch type definition mismatches.

### Verify

```bash
# Verify integration packages exist with platform-specific naming
find packages -type d -name 'twenty-*' | grep -E '(zapier|integration)' | wc -l

# Verify standard trigger patterns are implemented
grep -r 'list_record_ids\|find_object_names\|trigger_record' packages/twenty-zapier/src/triggers/ | wc -l

# Verify type definition files exist for external data contracts
find packages/twenty-zapier -name '*.types.ts' -o -name 'data.types.ts' | wc -l

# Verify modern build tooling is configured
grep -r 'vite.config' packages/twenty-zapier/ | wc -l
```

**Accept when:**
- At least one integration package exists under `packages/` with platform-specific naming (e.g., `twenty-zapier`)
- Standard trigger patterns (`list_record_ids`, `find_object_names`, `trigger_record`) are implemented in the integration package
- Type definition files exist for external data contracts in dedicated `.types.ts` files
- Modern build tooling (Vite or equivalent) is configured for integration packages
- OAuth 2.0 authentication, rate limiting, and audit logging are implemented for all external API endpoints
- Integration documentation and visual components are co-located in website sections
- Comprehensive error handling and logging are present in integration code

<enforcement>
Claude Code MUST NOT skip or defer verification. CI pipeline MUST fail if integration packages are missing required trigger patterns or type definitions. Pull requests MUST be blocked if external API changes are not reflected in integration package types. Security scanning MUST flag any direct database access or internal schema exposure in integration code. Monthly architecture reviews MUST identify and remediate pattern violations.
</enforcement>
