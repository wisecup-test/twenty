<rule_activation id="5305e4ca-a866-4552-81b8-97029ff74f2f" title="Standardize Field Input Hooks Pattern for Record Field UI Components: Field Input Hooks" applies_to="packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/**">
These rules are ALWAYS ACTIVE for all field input components and hooks in the twenty-front package's record-field UI layer.
</rule_activation>

### Rules

- **R-FIH-001** SHOULD: Field input hooks SHOULD encapsulate all state management and interaction logic specific to that field type.
- **R-FIH-002** MUST: Follow the naming convention `useOpen[FieldType]FieldInput` for hooks.
- **R-FIH-003** MUST: Follow the naming convention `[FieldType]FieldInput` for components.
- **R-FIH-004** MUST: Place hooks in `packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks/`.
- **R-FIH-005** MUST: Place components in `packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/components/`.
- **R-FIH-006** MUST: Ensure hooks return consistent interface patterns (open handlers, state values, callbacks) to maintain API predictability.
- **R-FIH-007** MAY: Simple field types (text, number, boolean) that require minimal state management may be exempted from dedicated hooks (EXC-001).

### Verify

```bash
# Verify hook naming convention and location
find packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks -name 'useOpen*FieldInput.tsx' | wc -l

# Verify hooks are used in components
grep -r 'useOpen.*FieldInput' packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/components/ | wc -l

# Verify directory structure
test -d packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks && test -d packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/components && echo 'Structure valid'
```

**Accept when:**
- All field input hooks follow the `useOpen[FieldType]FieldInput` naming pattern and are located in the hooks directory
- Each field input component in the components directory uses its corresponding dedicated hook
- The directory structure maintains separation between `hooks/` and `components/` within the `meta-types/input` module
- No field input components exist without corresponding dedicated hooks (except for documented EXC-001 exceptions)
