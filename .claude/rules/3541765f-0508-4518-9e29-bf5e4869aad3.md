<rule_activation id="3541765f-0508-4518-9e29-bf5e4869aad3" title="Standardize Field Input Hooks Pattern for Record Field UI Components: Field Input Components" applies_to="packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/**">
These rules are ALWAYS ACTIVE for all field input components and hooks in the record-field UI meta-types input module.
</rule_activation>

### Rules

- **R-FIH-001** SHOULD: Field input components SHOULD be implemented as separate components in the 'components' directory parallel to the 'hooks' directory.
- **R-FIH-002** MUST: Follow the naming convention `useOpen[FieldType]FieldInput` for hooks and `[FieldType]FieldInput` for components.
- **R-FIH-003** MUST: Place hooks in `packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks/` and components in the parallel `components/` directory.
- **R-FIH-004** MUST: Ensure hooks return consistent interface patterns (e.g., open handlers, state values, callbacks) to maintain API predictability across field types.
- **R-FIH-005** SHOULD: Each field input component in the components directory SHOULD use its corresponding dedicated hook.
- **R-FIH-006** MAY: Simple field types (text, number, boolean) that require minimal state management and do not benefit from dedicated hooks MAY be exempted (EXC-001).

### Verify

```bash
# Count useOpen*FieldInput hooks in hooks directory
find packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks -name 'useOpen*FieldInput.tsx' | wc -l

# Verify hooks are used in components directory
grep -r 'useOpen.*FieldInput' packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/components/ | wc -l

# Verify directory structure exists
test -d packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks && test -d packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/components && echo 'Structure valid'
```

**Accept when:**
- All field input hooks follow the `useOpen[FieldType]FieldInput` naming pattern and are located in the hooks directory
- Each field input component in the components directory uses its corresponding dedicated hook
- The directory structure maintains separation between `hooks/` and `components/` within the `meta-types/input` module
- Hook naming conventions are enforced via linting rules
- Field input components not using dedicated hooks are rejected in code review

<enforcement>
Claude Code MUST verify all rules via the provided bash commands before accepting field input component implementations. Violations MUST trigger CI warnings and code review rejection. Exceptions require documented approval from the Frontend Architecture Team with reference to exception ID.
</enforcement>
