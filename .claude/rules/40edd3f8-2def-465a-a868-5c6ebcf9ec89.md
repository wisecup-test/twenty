<rule_activation id="40edd3f8-2def-465a-a868-5c6ebcf9ec89" title="Adopt Zapier Integration Pattern for External API Exposure: External Provide Object" applies_to="packages/twenty-*/src/**/*">
These rules are ALWAYS ACTIVE for all external integration packages and Zapier-specific implementations.
</rule_activation>

### Rules

- **R-ZAPIER-001** MUST: External APIs MUST provide object metadata discovery mechanisms to enable dynamic integration configuration.
- **R-ZAPIER-002** MUST: All integration packages MUST follow the packages/twenty-{platform} naming convention.
- **R-ZAPIER-003** MUST: Standard trigger patterns (list_record_ids, find_object_names, trigger_record) MUST be implemented in integration packages.
- **R-ZAPIER-004** MUST: External data contracts MUST be defined in dedicated .types.ts files with comprehensive JSDoc documentation.
- **R-ZAPIER-005** MUST: Integration packages MUST use modern build tooling (Vite or equivalent) for bundling and optimization.
- **R-ZAPIER-006** MUST: OAuth 2.0 authentication, rate limiting, audit logging, and scope-based permissions MUST be implemented for all external API endpoints.
- **R-ZAPIER-007** MUST: Type definitions MUST be maintained in sync between core API and integration packages using automated type generation.
- **R-ZAPIER-008** MUST: Integration packages MUST NOT expose direct database access or internal schema details.
- **R-ZAPIER-009** SHOULD: Integration documentation and visual components SHOULD be co-located in website sections for improved discoverability.
- **R-ZAPIER-010** SHOULD: Comprehensive error handling and logging SHOULD be implemented to aid debugging of integration issues.

### Verify

```bash
# Verify integration packages exist with platform-specific naming
find packages -type d -name 'twenty-*' | grep -E '(zapier|integration)' | wc -l

# Verify standard trigger patterns are implemented
grep -r 'list_record_ids\|find_object_names\|trigger_record' packages/twenty-zapier/src/triggers/ | wc -l

# Verify type definition files exist
find packages/twenty-zapier -name '*.types.ts' -o -name 'data.types.ts' | wc -l

# Verify modern build tooling is configured
grep -r 'vite.config' packages/twenty-zapier/ | wc -l

# Verify no direct database access in integration code
grep -r 'prisma\|sequelize\|typeorm' packages/twenty-zapier/src/ | grep -v node_modules | wc -l

# Verify OAuth and security patterns
grep -r 'oauth\|OAuth2\|rate.limit\|audit.log' packages/twenty-zapier/src/ | wc -l
```

**Accept when:**
- At least one integration package exists under packages/ with platform-specific naming (e.g., twenty-zapier)
- Standard trigger patterns (list_record_ids, find_object_names, trigger_record) are implemented in the integration package
- Type definition files exist for external data contracts with JSDoc documentation
- Modern build tooling (Vite or equivalent) is configured for integration packages
- OAuth 2.0 authentication is implemented for external API endpoints
- No direct database access patterns are present in integration package code
- Integration documentation is co-located with implementation code
- Comprehensive error handling and logging are implemented

<enforcement>
Claude Code MUST NOT skip or defer verification of integration package structure, trigger patterns, type definitions, and security controls. All R-ZAPIER rules are mandatory for external integration implementations. Violations MUST be flagged in code review and CI pipeline checks MUST fail if required patterns are missing.
</enforcement>
