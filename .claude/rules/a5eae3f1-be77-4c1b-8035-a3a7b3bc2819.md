<rule_activation id="a5eae3f1-be77-4c1b-8035-a3a7b3bc2819" title="Adopt Canvas-Based Custom Visual Effects for Design System Theming: Canvas Rendering Logic" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files implementing custom visual effects in the design system, particularly feature cards, testimonials, hero sections, and themed UI components.
</rule_activation>

### Rules

- **R-CANVAS-001** SHOULD: Canvas rendering logic SHOULD be separated from component presentation logic to enable reusability across different themed sections.

### Verify

```bash
# Verify canvas hook naming conventions and usage patterns
grep -r "use-.*-canvas\|use-.*-backdrop" packages/twenty-website-new/src --include="*.ts" --include="*.tsx"

# Verify Canvas 2D API context initialization
grep -r "getContext\('2d'\)" packages/twenty-website-new/src --include="*.ts" --include="*.tsx"

# Run canvas and backdrop-related tests with coverage
npm run test -- --testPathPattern="canvas|backdrop" --coverage
```

**Accept when:**
- All custom visual effects requiring pixel manipulation are implemented as React hooks using Canvas API
- Canvas hooks follow consistent naming conventions (use-*-canvas or use-*-backdrop pattern) and encapsulate rendering logic separately from component structure
- Canvas elements include proper cleanup in useEffect return callbacks and respond appropriately to theme/viewport changes
- Canvas elements have appropriate ARIA labels and text alternatives for accessibility
- Performance budgets for canvas rendering operations are met and no regressions are detected in CI

<enforcement>
Claude Code MUST NOT skip or defer verification. All canvas-based visual effects implementations MUST pass the verify commands and accept-when criteria before approval. Code review checklist verification, automated tests for cleanup and memory leak prevention, and performance monitoring in CI are mandatory.
</enforcement>
