<rule_activation id="293642ff-a75a-4ad1-bee1-a36ddf766f7e" title="Adopt Zapier Integration Pattern for External API Exposure: Zapier Triggers Implement" applies_to="packages/twenty-*/src/**/*">
These rules are ALWAYS ACTIVE for all Zapier and external integration platform packages.
</rule_activation>

### Rules

- **R-ZAP-001** MUST: Zapier triggers MUST implement standard patterns including list_record_ids, find_object_names, and trigger_record for data discovery and synchronization
- **R-ZAP-002** MUST: All external data contracts MUST be defined in dedicated .types.ts files with comprehensive JSDoc documentation
- **R-ZAP-003** MUST: Integration packages MUST follow the packages/twenty-{platform} naming convention
- **R-ZAP-004** MUST: External API endpoints MUST implement OAuth 2.0 authentication, rate limiting, audit logging, and scope-based permissions
- **R-ZAP-005** MUST: Integration packages MUST use modern build tooling (Vite or equivalent) for bundling and optimization
- **R-ZAP-006** MUST: Type definitions MUST be automatically generated from core API schemas to prevent drift
- **R-ZAP-007** MUST: Integration code MUST NOT access internal databases or expose internal schemas directly
- **R-ZAP-008** SHOULD: Integration documentation and visual components SHOULD be co-located in website sections for improved discoverability
- **R-ZAP-009** SHOULD: Comprehensive error handling and logging SHOULD be implemented to aid debugging of integration issues

### Verify

```bash
# Verify integration packages exist with platform-specific naming
find packages -type d -name 'twenty-*' | grep -E '(zapier|integration)' | wc -l

# Verify standard trigger patterns are implemented
grep -r 'list_record_ids\|find_object_names\|trigger_record' packages/twenty-zapier/src/triggers/ | wc -l

# Verify type definition files exist
find packages/twenty-zapier -name '*.types.ts' -o -name 'data.types.ts' | wc -l

# Verify modern build tooling is configured
grep -r 'vite.config' packages/twenty-zapier/ | wc -l

# Verify no direct database access in integration code
grep -r 'prisma\|sequelize\|typeorm' packages/twenty-zapier/src/ | grep -v node_modules | wc -l

# Verify OAuth implementation in external API endpoints
grep -r 'oauth\|OAuth' packages/twenty-zapier/src/ | wc -l
```

**Accept when:**
- At least one integration package exists under packages/ with platform-specific naming (e.g., twenty-zapier)
- Standard trigger patterns (list_record_ids, find_object_names, trigger_record) are implemented in the integration package
- Type definition files exist for external data contracts with JSDoc documentation
- Modern build tooling (Vite or equivalent) is configured for integration packages
- OAuth 2.0 authentication is implemented for all external API endpoints
- No direct database access or internal schema exposure exists in integration code
- Integration tests validate Zapier trigger implementations against platform requirements
- Type definitions are generated from core API schemas or maintained with contract testing
