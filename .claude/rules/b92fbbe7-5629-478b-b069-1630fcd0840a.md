<rule_activation id="b92fbbe7-5629-478b-b069-1630fcd0840a" title="Standardize Field Input Hooks Pattern for Record Field UI Components: Field Input Components" applies_to="packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/**">
These rules are ALWAYS ACTIVE for all field input components in the record-field UI layer of the twenty-front package.
</rule_activation>

### Rules

- **R-FIH-001** MUST: All field input components in the record-field UI layer MUST use dedicated custom hooks following the naming pattern `useOpen[FieldType]FieldInput`.
- **R-FIH-002** MUST: Place hooks in `packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks/` and components in the parallel `components/` directory.
- **R-FIH-003** MUST: Follow the naming convention: `useOpen[FieldType]FieldInput` for hooks and `[FieldType]FieldInput` for components.
- **R-FIH-004** MUST: Ensure hooks return consistent interface patterns (e.g., open handlers, state values, callbacks) to maintain API predictability across field types.
- **R-FIH-005** SHOULD: When creating a new field input type, start by copying an existing hook (e.g., `useOpenFilesFieldInput.tsx`) as a template and adapt it to the new field type's requirements.
- **R-FIH-006** MAY: Simple field types (text, number, boolean) that require minimal state management and do not benefit from dedicated hooks are exempt from this pattern (EXC-001).

### Verify

```bash
# Count hooks following the naming pattern
find packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks -name 'useOpen*FieldInput.tsx' | wc -l

# Verify components use their corresponding hooks
grep -r 'useOpen.*FieldInput' packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/components/ | wc -l

# Verify directory structure exists
test -d packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks && test -d packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/components && echo 'Structure valid'
```

**Accept when:**
- All field input hooks follow the `useOpen[FieldType]FieldInput` naming pattern and are located in the hooks directory
- Each field input component in the components directory uses its corresponding dedicated hook
- The directory structure maintains separation between `hooks/` and `components/` within the `meta-types/input` module
- Simple field types (text, number, boolean) are documented with exception reference EXC-001 if they do not use dedicated hooks

Claude Code MUST verify all rules before approving field input component implementations. Violations result in CI warnings and code review rejection. Exceptions require Frontend Architecture Team approval and must be documented with exception ID in component file comments.
