<rule_activation id="55f38e82-2988-4a09-810d-d5dc589592df" title="Adopt Zapier Integration Pattern for External API Exposure: External Integrations Not" applies_to="**/*">
These rules are ALWAYS ACTIVE for all files matching external integrations, Zapier packages, and public API contracts.
</rule_activation>

### Rules

- **R-ZAP-001** MUST_NOT: External integrations MUST NOT expose internal database schemas or implementation details directly.
- **R-ZAP-002** MUST: Create new integration packages under `packages/twenty-{platform}` following the established `twenty-zapier` structure.
- **R-ZAP-003** MUST: Define all external data contracts in dedicated `.types.ts` files with comprehensive JSDoc documentation.
- **R-ZAP-004** MUST: Implement standard trigger patterns: `list_record_ids` for polling, `trigger_record` for webhooks, and `find_object_names` for dynamic configuration.
- **R-ZAP-005** MUST: Use Vite or similar modern bundlers to ensure compatibility with platform requirements and optimize bundle size.
- **R-ZAP-006** SHOULD: Co-locate integration documentation and visual components in website sections for improved discoverability.
- **R-ZAP-007** MUST: Implement comprehensive error handling and logging to aid debugging of integration issues.
- **R-ZAP-008** MUST: Implement OAuth 2.0 authentication, rate limiting, audit logging, and scope-based permissions for all external API endpoints.

### Verify

```bash
# Verify integration package structure and naming
find packages -type d -name 'twenty-*' | grep -E '(zapier|integration)' | wc -l

# Verify standard trigger patterns are implemented
grep -r 'list_record_ids\|find_object_names\|trigger_record' packages/twenty-zapier/src/triggers/ | wc -l

# Verify type definition files exist
find packages/twenty-zapier -name '*.types.ts' -o -name 'data.types.ts' | wc -l

# Verify modern build tooling is configured
grep -r 'vite.config' packages/twenty-zapier/ | wc -l
```

**Accept when:**
- At least one integration package exists under `packages/` with platform-specific naming (e.g., `twenty-zapier`)
- Standard trigger patterns (`list_record_ids`, `find_object_names`, `trigger_record`) are implemented in the integration package
- Type definition files exist for external data contracts
- Modern build tooling (Vite or equivalent) is configured for integration packages
- No direct database access or internal schema exposure is present in integration code
- OAuth 2.0 authentication and rate limiting are implemented for external API endpoints

<enforcement>
Claude Code MUST verify all R-ZAP rules before approving changes to external integrations, Zapier packages, or public API contracts. CI pipeline MUST fail if integration packages are missing required trigger patterns or type definitions. Security scanning MUST flag any direct database access or internal schema exposure in integration code.
</enforcement>
