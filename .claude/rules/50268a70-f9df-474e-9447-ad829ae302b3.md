<rule_activation id="50268a70-f9df-474e-9447-ad829ae302b3" title="Standardize Field Input Hooks Pattern for Record Field UI Components: Hook Implementations Maintain" applies_to="packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/**/*">
These rules are ALWAYS ACTIVE for all field input components and hooks in the record-field UI module.
</rule_activation>

### Rules

- **R-FIHP-001** MUST: Hook implementations MUST maintain consistent API patterns across different field types to ensure predictable usage.
- **R-FIHP-002** MUST: Follow the naming convention `useOpen[FieldType]FieldInput` for hooks and `[FieldType]FieldInput` for components.
- **R-FIHP-003** MUST: Place hooks in `packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks/` and components in the parallel `components/` directory.
- **R-FIHP-004** MUST: Each field input component in the components directory MUST use its corresponding dedicated hook.
- **R-FIHP-005** SHOULD: When creating a new field input type, start by copying an existing hook (e.g., `useOpenFilesFieldInput.tsx`) as a template and adapt it to the new field type's requirements.
- **R-FIHP-006** SHOULD: Ensure hooks return consistent interface patterns (e.g., open handlers, state values, callbacks) to maintain API predictability across field types.
- **R-FIHP-007** MAY: Simple field types (text, number, boolean) that require minimal state management and do not benefit from dedicated hooks are exempt from this pattern (EXC-001).

### Verify

```bash
# Verify hook naming convention compliance
find packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks -name 'useOpen*FieldInput.tsx' | wc -l

# Verify hooks are used in components
grep -r 'useOpen.*FieldInput' packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/components/ | wc -l

# Verify directory structure
test -d packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/hooks && test -d packages/twenty-front/src/modules/object-record/record-field/ui/meta-types/input/components && echo 'Structure valid'
```

**Accept when:**
- All field input hooks follow the `useOpen[FieldType]FieldInput` naming pattern and are located in the hooks directory
- Each field input component in the components directory uses its corresponding dedicated hook
- The directory structure maintains separation between `hooks/` and `components/` within the `meta-types/input` module
- No field input components exist outside the established directory structure without documented exceptions
